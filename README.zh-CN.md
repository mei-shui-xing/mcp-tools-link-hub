# 给 ChatGPT 使用的三个 MCP 项目

[English](README.md)

这是一个轻量的项目入口，整理了三个彼此独立的实验性 MCP 项目，分别用于操作抖音与创作者中心、Windows 电脑和 Android 手机。

它们主要是为了更方便地交给 ChatGPT 使用而整理的，其他兼容 MCP 的客户端也可以参考各项目文档接入。

这里不是代码合集，也不是一个需要整体安装的新框架或品牌。三个项目继续保留各自的源码、版本、Release、许可证、安全边界和问题追踪。你只需要根据自己的需求选择其中一个项目，不必全部安装。

> 这些项目均为独立社区项目，与 OpenAI、ChatGPT、抖音、字节跳动、Android 和 Microsoft 官方无关。

## 它们是怎么长出来的

最开始其实没有计划做三个项目。

最早的 MVP 很简单：只是想让 ChatGPT 看看我自己的抖音收藏。后来在实际使用过程中，才一点点加入读取作品和评论、查看创作者中心、回复评论、发布作品等功能。

不过抖音网页本身经常变化，部分操作也容易遇到平台风控。即使加入结构化识别、操作后回读和各种安全限制，有些功能仍然可能受到页面状态、账号环境或平台限制影响。

为了方便调试抖音项目，也为了在专用功能暂时不可用时提供一个通用兜底，过程中又做了 Windows 电脑桥。后来中途突然对控制手机产生兴趣，于是又折腾出了 Android 手机 MCP。

有点好笑的是，原本为了调试和兜底出现的电脑桥，以及后来临时起意做的手机控制，在不少日常场景里反而更通用、更流畅。尤其是抖音本来就以手机端为主，很多操作直接控制手机会比操作电脑网页自然一些。

但这并不意味着抖音专用项目没有价值。电脑和手机控制通常需要根据当前屏幕一步步操作，而 Douyin Controlled MCP 可以读取结构化状态。需要集中查看创作者中心的多条后台评论、筛选内容、确认具体作品或评论目标时，它仍然比单纯截图和点击方便很多。

所以最后干脆把三个项目都公开。需要哪个就使用哪个，不必全部安装。

## 应该选择哪一个

| 场景 | 推荐项目 | 主要优势 |
| --- | --- | --- |
| 抖音与创作者中心 | **Douyin Controlled MCP** | 结构化读取作品、评论和创作者中心状态，尤其适合集中查看与筛选多条后台评论 |
| Windows 电脑 | **AI Desktop Control Bridge** | 文件、终端、进程、截图和带安全限制的可见桌面操作 |
| Android 手机 | **Android Remote Control MCP** | 直接操作应用、屏幕、触摸、文字、文件和其他设备能力 |

### Douyin Controlled MCP

适合：

- 查看自己的抖音收藏、作品和评论；
- 集中读取创作者中心的多条后台评论；
- 根据明确目标回复评论；
- 在本人确认后进行发布等写入操作；
- 希望尽量通过结构化状态确认目标，而不是完全依赖截图点击。

它不是无人值守的账号运营系统。抖音页面、账号环境和风控策略可能随时变化，部分功能可能需要重新适配。

### AI Desktop Control Bridge

适合：

- 读取和修改本机文件；
- 执行终端命令；
- 启动、停止或检查进程；
- 获取窗口、截图和可见界面状态；
- 操作经过允许的 Windows 桌面程序；
- 检查、安装、构建、测试和修复另外两个项目。

电脑桥不仅可以独立完成通用电脑任务，也可以作为 Douyin Controlled MCP 和 Android Remote Control MCP 的本地安装、调试和维修入口。

### Android Remote Control MCP

适合：

- 直接操作 Android 应用；
- 点击、滑动、输入文字和读取屏幕状态；
- 管理文件、应用、通知和部分设备能力；
- 完成原本就在手机端更自然的任务；
- 不希望所有操作都依赖电脑网页或持续连接 ADB。

MCP 服务直接运行在 Android 手机上。需要调试本机环境时，也可以由用户连接 USB 并确认调试授权，再让已连接电脑桥的 AI 使用 ADB 检查安装、权限、服务状态和脱敏日志。

## 推荐的安装与维修顺序

如果只需要其中一个项目，可以直接安装对应项目，不必三个全部配置。

如果准备长期使用，或者希望后续出现问题时能让 AI 自己检查和修复，建议优先连接 **AI Desktop Control Bridge**。

电脑桥成功连接后，AI 可以在设备所有者允许的范围内：

- 阅读和修改项目文件；
- 执行安装、构建、测试和诊断命令；
- 查看进程、窗口、日志和本机环境；
- 修复 Douyin Controlled MCP 的代码或配置问题；
- 手机通过 USB 连接后，使用 ADB 检查 Android 项目的环境；
- 根据当前报错进行最小范围修复并重新测试。

敏感操作仍然必须由设备所有者本人处理，包括账号登录、密码、验证码、生物识别、付款、系统权限、USB 调试授权和其他安全确认。

不要让多个 AI 对话同时控制同一套鼠标键盘、同一个浏览器会话或同一部手机。

## 让自己的 AI 安装和修复

每个项目都尽量提供了适合 AI 阅读的安装、配置、测试和排障文档。

打开需要使用的项目仓库后，可以对 AI 编程助手这样说：

> 请完整阅读这个仓库的 README、AI 配置、安全说明和排障文档，在当前设备上完成安装与配置。
>
> 如果出现错误，请先检查本机环境、依赖、配置和脱敏日志，再阅读相关代码，进行最小范围修复并运行项目提供的测试。
>
> 不要把密码、令牌、Cookie、浏览器配置、本机专用地址、私人聊天或未脱敏日志提交到 Git。
>
> 遇到账户登录、验证码、生物识别、付款、USB 调试授权、敏感权限或其他必须由设备所有者本人处理的步骤时暂停，并明确告诉我需要完成什么。
>
> 不要通过关闭安全检查、绕过平台限制或盲目重复高风险操作来强行解决问题。

如果电脑桥已经连接，还可以直接告诉 AI：

> 请通过电脑桥检查这个项目当前的报错。阅读仓库文档和相关代码，检查依赖、配置与日志，进行最小修复并运行测试。不要修改无关功能，也不要提交任何本机私有信息。

手机项目需要调试时，可以先由本人连接 USB 并确认调试授权，再告诉 AI：

> 手机已经通过 USB 连接。请按照仓库文档检查 ADB、安装状态、权限和 MCP 服务配置，收集脱敏日志并修复当前问题。锁屏密码、生物识别、账号登录和权限确认由我本人完成。

## 建议创建本机启动脚本

电脑桥首次配置成功后，建议让 AI 根据当前电脑的真实安装路径，在桌面创建一个**本机专用的启动与状态检查脚本**，方便电脑重启后继续连接。

脚本可以负责：

- 检查必要运行环境和依赖；
- 启动电脑桥及其本地组件；
- 显示当前运行状态和连接入口；
- 检查端口、进程和基础配置；
- 在启动失败时指出日志位置和排障提示；
- 提供停止和重新启动入口。

建议同时创建一份简短的本机说明，记录：

- 项目的本机安装路径；
- 正确的启动顺序；
- 状态检查方法；
- 常见日志位置；
- 停止和紧急中断方式；
- 重启电脑后应该先运行哪个脚本。

可以对 AI 这样说：

> 电脑桥已经可以正常使用。请根据当前实际安装路径，在桌面创建一个本机专用的启动与状态检查脚本，方便电脑重启后恢复环境。
>
> 脚本应检查依赖、启动服务、显示状态和日志位置，并提供停止或重启入口。不要把令牌、Cookie、密码、私有连接地址或其他凭据直接写进桌面脚本；敏感配置继续保存在项目规定的 Git 忽略目录中。

桌面脚本和本机说明只属于当前电脑，不应上传到公共仓库，也不应包含任何凭据。

## 出现 Bug 时怎么办

这些项目都是实验性 Alpha，无法提前覆盖所有电脑、浏览器、Android 机型、厂商系统、VPN、驱动和账号环境。

遇到问题时，建议：

1. 把仓库地址、具体报错、发生步骤和脱敏日志交给自己的 AI；
2. 让 AI 完整阅读最新 README、配置说明、安全文档和已知问题；
3. 检查依赖、配置、进程、网络和权限状态；
4. 确认是代码问题后，让 AI 进行最小范围修复；
5. 运行仓库提供的类型检查、构建、测试或本机验收脚本；
6. 确认修复没有泄露私有配置，也没有削弱安全边界；
7. 确实属于通用代码问题时，再整理可复现步骤或 Pull Request。

电脑桥连通后，理论上已经具备检查项目、修改代码、运行测试，以及通过 USB 调试手机环境所需的大部分本地能力。

因此，有 Bug 时优先让使用者自己的 AI 阅读文档、检查环境并尝试修复。项目作者不负责为每台电脑、手机、网络、账号和代理环境提供人工兜底。

## 使用边界

三个项目目前都属于实验性 Alpha 软件。

使用前请阅读对应项目自己的安全说明，并遵守以下原则：

- 密码、验证码、生物识别、付款和身份验证必须由设备所有者本人处理；
- 账号登录、权限授予和敏感设置变更需要本人确认；
- 不要公开 Cookie、访问令牌、浏览器配置、私人聊天或未脱敏日志；
- 不要让多个 AI 对话同时控制同一个浏览器、鼠标键盘或手机；
- 优先使用结构化信息和操作后的回读验证；
- 截图和坐标点击只作为无法结构化识别时的兜底；
- 不要绕过系统安全边界、平台风控或账号限制；
- 使用者自行确认其用途符合平台规则和当地法律。

这些工具不应被用于未经授权的账号、设备或数据。

## 关于维护

这些项目公开的目标，是让使用者可以把仓库交给自己的 AI，根据文档自行完成安装、配置、调试和必要的本地修复。

后续维护属于尽力而为：

- 不提供逐台电脑或手机的远程安装服务；
- 不保证适配所有浏览器、Android 系统、厂商 ROM、VPN、驱动或账号环境；
- 不承诺固定回复时间；
- 不负责无法复现的个人环境问题；
- 平台网页、风控策略或系统行为变化后，部分功能可能需要使用者让自己的 AI 重新适配；
- 不建议等待项目作者针对个人环境提供专门修复。

能够稳定复现、与特定个人环境无关的代码问题，可以提交包含完整信息且已经脱敏的 Issue 或 Pull Request。
